### Implemented #179 identity rule

The backend does not claim to understand arbitrary prose. An AgentToken supplies a declared bounded `semanticTopic`, and the database hashes the authenticated subject, local date, timezone, normalized declared topic, sorted owned current source references (including a mandatory current `revisionId`), and optional parent question. Prompt punctuation, thread identity, and client idempotency key are intentionally excluded. Thus retries and cross-thread paraphrases of the same declared topic/source/day resume one question, while changed source revisions, a different source, a different day, or a legitimate new topic produce a distinct question. A stale, missing, wrong-kind, foreign, or soft-deleted source is rejected without disclosing ownership.

Current revision tokens are domain revision ids for revision-authoritative Activity, body-context, proposal, question, and answer records; the immutable recurrence-revision id for recurrence revisions; and a deterministic `sha256:` semantic fingerprint for mutable goals, workout sessions (including sets), scheduled workout snapshots (including exercises/sets), nutrition logs (including meals/items), meals (including items), and observations. Callers must copy a token from current readback rather than synthesize it. Follow-ups require an answered owned parent, retain the parent/source entity links, dedupe across threads at the same current source version, and form a new canonical identity after a relevant source-version change. An answered question remains answered under its canonical identity; a new prompt alone cannot requeue it.

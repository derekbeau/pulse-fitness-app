## Additional reconciled surfaces

- `packages/shared/src/schemas/feedback-provenance.ts`: one classifier and actionability predicate. The parser, direct progression/nutrition consumers, and score cards use it. Reserved native IDs cannot declare a conflicting construct. Tests distinguish all native values/states and reject metadata-only trust.
- `apps/api/src/middleware/agent-enrichment.ts`: the workout mutation enrichment reads status, native sets and next exercise only. No feedback score or raw note audit is incorporated. `/api/v1/context` recent-workout queries select IDs/names/dates and aggregate native performance, preserving history links without feedback summaries.
- `apps/api/src/middleware/feedback-note-projection.ts`: owner/stable-parent/exact-text projection at API output; nested exercise notes in session outputs are also checked. Pending source text stays unchanged with `actionable:false` review metadata. Confirmed text is suppressed only from active projection. Template/scheduled start copying uses the planning-copy option to omit both pending and superseded interpretations; source records remain unchanged. Raw mutation merge inputs stay unprojected to avoid overwriting originals.
- `apps/web/src/features/workouts/components/{feedback-audit,template-detail,scheduled-workout-detail,exercise-detail-modal,session-detail}.tsx` and `pages/active-workout.tsx`: explicit review marker and private audit disclosure; raw audit has no clinical actionability. Session history displays unverified actor warning and nullable score cards independently apply the shared predicate.
- `packages/shared/src/schemas/{exercises,scheduled-workouts,workout-templates,workout-sessions}.ts`: preserve review metadata through typed clients; request schemas do not accept note audit metadata as evidence.
- `apps/web/src/lib/query-invalidation.ts`: session mutations now invalidate adaptive reviews and progression previews as well as prior dashboard/history/habit keys. Query cache is in-memory; no persistent server-state cache found in query-client.ts. Existing old-client tabs remain subject to API quarantine and server fingerprint rejection.
- `apps/api/src/routes/workout-progression/store.ts` and `db/schema/workout-progression.ts`: cached recommendation snapshots are immutable audit records. The evidence fingerprint has feedback version 2; old snapshots become stale and actions recheck current fingerprint. No prose regex remediation rewrites a snapshot or target. Integration test verifies unsupported legacy technique/false pain supply no feedback fact, explicit technique revisions change the fingerprint, and the prior recommendation remains readable as stale.
- `apps/api/src/routes/adaptive-nutrition/review-store.ts`: snapshot source fingerprint version 2 with feedback evidence version; existing review refresh/supersession mechanism preserves old audit snapshots. Missing recovery is not a 5; unavailable values are excluded from averages and conditions. Preview regression fixtures now supply actual explicit recovery evidence when testing a low-recovery module.
- `apps/web/e2e/rir-history-fixture.ts`: a separate opt-in synthetic fixture still sends an old-client payload. It is intentionally retained to exercise compatibility; the API quarantines its unsupported ratings. No real fixture or completed performance is rewritten.
- `apps/api/drizzle/0061_feedback_provenance_audit.sql` and new ORM schemas: additive audit, submission, ledger and note-disposition tables only. Earlier migrations and staged rehearsal tests remain unchanged. Ledger includes skipped/preserved source markers and exact source evidence. New synthetic migration fixtures use the full real schema.
- Synthetic seed, rehearsal and CLI scripts use only explicitly created temporary fictional databases. `migrate-static.ts` historical null-feedback imports remain unchanged and were not executed. The ordinary default-database migration runner is not used by this capability.

The final source search is retained in `consumer-search-final.txt`; it is a cross-check, not proof by itself. No identified actionable score consumer is intentionally deferred. Native set performance, symptoms and timing remain independent evidence. Cached recommendation prose is preserved as immutable, stale audit history rather than regex-rewritten coaching notes.
